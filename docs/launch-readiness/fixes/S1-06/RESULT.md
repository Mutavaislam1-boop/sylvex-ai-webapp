# S1-06 — XSS на страницах аккаунта сайта

09.11.2026. **Статус: XSS устранён и развёрнут** (10.11.2026). SQL-инъекции остаются отдельной непроверенной частью S1-06.

## Дефект
Данные аккаунта вставлялись в `innerHTML` без экранирования:
- `account/profile.html` — имя, `username`, email (текст и атрибуты `data-*`), OAuth-метки, тариф, `avatar_url` (в `src`);
- `account/settings.html` — имя (в атрибут `value` поля ввода), email (3 места), OAuth-метки, SYLVEX ID, «с нами с»;
- `js/site.js` — общий аватар в шапке (`avatar_url` в `src`), подключается на 30 страницах.

API проверяет имя только по длине (до 60 символов, `main.py:18756`), поэтому имя вида `<img src=x onerror=…>` выполняло скрипт.

**Серьёзность низкая.** Страницы показывают данные только самого владельца аккаунта: в Mini App и Studio чужие имена экранируются, в шапке имя выводится через `textContent`.

## Исправление
- Ветка `claude/s106-account-escape`, коммит `968e928`, основа — `main` `821d151`.
- Каждое значение экранируется для своего контекста: `&<>"'` для текста и атрибутов в двойных кавычках.
- На профиль добавлен тот же экранировщик, что уже был в настройках; `site.js` использует свой `escapeHtmlLocal`.
- Механизмы Codex (CSRF, авторизация, Rate Limiting, SQL) не тронуты.
