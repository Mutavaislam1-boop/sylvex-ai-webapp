**Результат:**

Тесты кода `tests/test_canonical_identity.py`: заполнение, триггер и создание ID проходят (6 passed). 10 других падений в файле (сценарии объединения с сайтом) совпадают на b244195 и прежнем Production-коде 7a35c7f/deac8e1, то есть существовали до B09.

## Финальная версия для редактора Railway (заменяет BEGIN/COMMIT-варианты шагов 5 и 6)

**4c в Production:** ровно четыре ожидаемые строки (users 3, user_events 1, user_profiles 1, user_referrals 1), реферальных связей 0.

**Как устроены шаги 5 и 6.**
- Каждый — **одна команда `DO`**. В PostgreSQL одна команда всегда атомарна, поэтому `BEGIN`/`COMMIT` не нужны: редактор может выполнять команды по отдельности.
- Тайм-ауты ставятся внутри команды (`set_config(..., true)`).
- При любом несоответствии — `RAISE EXCEPTION 'STOP: …'` и полный откат.

**Порядок:**
0. Свежая копия тома (Backups). Рекомендуется Backup now непосредственно перед шагом 6.
1. 4c-0 — снимок ДО.
2. 6 → 6b.
3. 5a → 5.
4. 7.

| Шаг | Файл | Тип | Ожидаемо / остановка |
|---|---|---|---|
| 6 | `6_delete_test_accounts.sql` | запись, одна команда | заранее сверяет 3 / 1 / 1 / 1 и все защиты, затем удаляет с проверкой числа строк |
