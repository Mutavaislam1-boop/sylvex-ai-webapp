## 2. Что должен подтвердить владелец до деплоя

1. **TOTP владельца.** Откройте консоль → «Администраторы» и проверьте, что в столбце 2FA у вас «вкл.». Либо выполните запрос 1 из `fixes/B10/owner_admin_mfa_readonly.sql`.
   - Если 2FA выключена, это не блокировка: после деплоя Mini App откроет экран настройки. Но удобнее настроить заранее (Аккаунт и безопасность → «Настроить аутентификатор»).
2. **Аутентификатор под рукой.** Резервная копия ключа хранится офлайн (менеджер паролей или бумага). Ключ и коды никому не отправлять, в том числе мне.
3. **Аварийное восстановление.** У вас есть доступ к Railway → Postgres → Query (для SQL из `ADMIN_TOTP_GUIDE.md`, раздел 4) и к откату деплоя в Railway.
4. **Окно деплоя.** Нет критичных административных операций. Остальные администраторы предупреждены, что после деплоя понадобится код (третьему — настроить 2FA).

## 4. Откат

Откат идёт в обратном порядке: main bot → support bot → API. Без force push.

- **Быстро:** Railway → сервис → Deployments → предыдущий деплой → Rollback:
  - API — be0686d8 (5dbcde1);
  - support — 023b1104 (f9cd89e);
  - bot — f7837266 (b7e1b90).
- **Затем в git:** `git revert` коммита на той же ветке, чтобы следующий push не вернул изменения.
- **Базу данных** откатывать не нужно: новые столбцы старый код игнорирует. Настроенные администраторами TOTP остаются рабочими для входа в браузере.
- **Если откатить только API** при новых ботах:
  - support bot работает как раньше: блок `mfa` отсутствует, поэтому он пускает;
  - main bot отказывает в `/admin` и `/addbalance`, пока API не вернут, — это безопасный отказ. Поэтому при откате API откатываются и боты.

## 5. Ручная проверка MFA на Production (≈10 минут, без платных действий)

Выполняет владелец. Код вводится только в окне SYLVEX Admin.

1. **Mini App: нужен код.** Бот поддержки → «🖥 SYLVEX Admin». Ожидаемо: поле «Код 2FA», консоль не открыта.
2. **Неверный код.** Ввести `000000`. Ожидаемо: «Код неверный. Введите текущий код из аутентификатора.», консоль не открыта. (Не вводить неверный код 5 раз — сработает блокировка на 15 минут.)
3. **Верный код.** Ввести код из приложения. Ожидаемо: консоль открылась; «Аккаунт и безопасность» → «Боты SYLVEX могут выполнять ваши действия до …».
4. **Повтор того же кода.** Закрыть и снова открыть Mini App, ввести тот же код в течение 30 секунд. Ожидаемо: отказ. Следующий код подходит.
5. **Критическое действие.** Подождать больше 5 минут, затем в «Администраторы» открыть «Изменить» у не-владельца и сохранить без изменений, указав причину. Ожидаемо: запрос «Подтвердите, что это вы» только по коду 2FA, кнопки «Подтвердить через Telegram» нет.
6. **Бот без подтверждения.** «Аккаунт и безопасность» → «Выйти на всех устройствах». Затем в боте поддержки открыть, например, «Дашборд». Ожидаемо: сообщение «🔐 Подтвердите вход кодом 2FA» и кнопка «🔐 Подтвердить 2FA», без просьбы прислать код в чат.
7. **Подтверждение для бота.** Нажать «🔐 Подтвердить 2FA», ввести код. Ожидаемо: «Подтверждено… 30 минут» → «Вернуться в бот». Раздел бота открывается.
8. **Main bot.** Отправить `/admin`. Ожидаемо: статистика, так как подтверждение свежее. Через 31 минуту без подтверждения или после «Выйти на всех устройствах»: кнопка «🔐 Подтвердить 2FA» и никаких данных. `/addbalance` не выполнять: команда меняет баланс.
9. **Браузер.** `https://api.sylvex.ai/admin/`: email + пароль + код, как раньше.
10. **Администратор без 2FA** (третий): открывает SYLVEX Admin → экран «Двухфакторная аутентификация обязательна…» → настраивает → консоль открывается с правами его роли.

После шагов 1–9 (и 10, когда третий администратор его выполнит) можно закрывать в реестре S1-05 и S7-09 по результатам ручной проверки. До этого реестр не меняется.
