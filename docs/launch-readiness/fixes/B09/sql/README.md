# B09 / S7-04 — SYLVEX ID для 22 старых Telegram-пользователей

Пользователи, впервые пришедшие до 22.10.2026, не имеют строки `sylvex_accounts`: триггер появился позже, а разовое заполнение в Production не запускалось. Без этой строки обработчик удаления отвечает `telegram_account_not_found`.

**Production (проверено владельцем):** `missing = 22`, `test_account_missing = 1`, все три проверки схемы = 1.

## Порядок (Railway → Postgres → Data → Query)

1. `1_preview.sql` — только чтение. Ожидаемо `missing = 22`, `test_account_missing = 1`.
2. `2_backfill.sql` — запись, одна транзакция. Ожидаемо `inserted = 22`. Иначе ROLLBACK.
3. `3_verify.sql` — только чтение. Ожидаемо `missing = 0`; у 7772859187 одна строка: `telegram`, `not_merged = true`, первоначальная дата.

## Проверка

`check_backfill_sql.py` прогоняет все три файла на изолированной локальной PostgreSQL, где схема создана кодом приложения (`ensure_account_tables`) и установлены защитные триггеры удаления. Синтетические данные:
- 22 старых пользователя с текстовыми датами разных форматов, включая пустую и нечитаемую;
- пользователь с уже существующим ID;
- объединённый псевдоним;
- ключ хранения сайта;
- покупки и подписки.

**Результат:**
- `preview` = 22 / 1;
- `inserted` = 22, затем `missing` = 0;
- существующие строки и ID не изменились; ключ хранения сайта и объединённый псевдоним не получили строк;
- балансы, покупки и подписки совпадают до и после;
- у тестового аккаунта сохранена дата `2026-10-21 11:45:24`, ID в формате SS 0626 99 NNNN; пустые и нечитаемые даты → NOW();
- `telegram_erasure.check_scope(7772859187)` находит аккаунт;
- повторный запуск вставляет 0.

Тесты кода `tests/test_canonical_identity.py`: заполнение, триггер и создание ID проходят (6 passed). 10 других падений в файле (сценарии объединения с сайтом) совпадают на b244195 и прежнем Production-коде 7a35c7f/deac8e1, то есть существовали до B09.

**Защиты шага 6.** Удаление прерывается целиком, если у тестового ID:
- есть SYLVEX ID;
- он администратор (`admin_users`);
- есть незавершённая генерация;
- есть файлы в хранилище (`sylvex_storage_ownership`).

Платёжные таблицы удаляются только по отдельному решению. Динамического удаления «по всем таблицам» нет намеренно.
