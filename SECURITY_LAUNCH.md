# Проверенные изменения и запуск

Изменения сохраняют каталоги моделей, промпты, UI-разметку, цены пакетов и настройки провайдеров. Авторизация и ввод/вывод защищены отдельными модулями; платежи стали атомарными; генерация по шаблонам проходит через существующую очередь. Исходный `.env`, старая `.venv`, изображения/видео и рабочая БД не изменяются при переносе кода.

## Окружение

Требуется Python 3.12. Создать отдельную `.venv-secure`, установить `requirements.txt` (он использует проверенный `requirements.lock`). Запуск: `./scripts/run-local.sh`. Старую `.venv` можно сохранить для отката. Для production предусмотрены Dockerfile, исключающий `.env` из образа, непривилегированный пользователь, проверка обязательных параметров и healthcheck Railway.

`/health/live` проверяет процесс. `/health/ready` проверяет доступность БД и возвращает 503 при её отсутствии. Production startup дополнительно проверяет обязательные секреты, R2 и запрет тестовых режимов. Настройки окружения из `.env.example` нужно перенести в secret manager/панель хостинга, а не коммитить в Git.

## Требуемые действия перед production

1. Настроить приватный R2: bucket, endpoint и credentials. Отключить публичный r2.dev/custom-domain доступ в Cloudflare. `R2_PUBLIC_BASE_URL` оставить пустым. Если история уже содержит старые публичные URL, записать их прежний origin в `LEGACY_R2_PUBLIC_BASE_URL`: приложение сможет читать соответствующие объекты через приватный proxy, сохранив историю. Старые публичные ссылки R2 нельзя закрыть только изменением кода приложения.
2. Создать `TELEGRAM_PAYMENT_WEBHOOK_SECRET` и зарегистрировать ТО ЖЕ значение при setWebhook. Не менять существующий webhook вслепую: согласовать его URL с процессом бота, чтобы не отключить приём остальных событий. Без секрета HTTP-обработчик Stars отвечает 503 и не обрабатывает платежи; остальное приложение запускается с предупреждением.
3. Включить `APP_ENV=production`, HTTPS `WEBAPP_URL`, проверить DB/R2 secrets, PayPal webhook ID и режим live/sandbox. `ENABLE_DEV_PAYMENTS=0`, `PROSTUDIO_MOCK_GENERATION=0`. На Railway production определяется также по `RAILWAY_ENVIRONMENT_ID`.
4. Выбрать дневные/минутные квоты под тарифы и бюджет. Они общие для затратных helper-маршрутов, а не отдельные на каждый endpoint. Тарифы text/music/voice не придуманы заново: где исходный код не задавал стоимость, сохраняется прежняя экономика, но доступ требует подписи и ограничивается квотами. Проверку реальной стоимости этих режимов нужно выполнить по действующим тарифам провайдеров.
5. Снять резервную копию БД. Обновление добавляет `generation_reservations` и `sylvex_request_limits`, не удаляет существующие таблицы/данные. Проверить схему на копии production-БД, в особенности существующие users/subscriptions/purchases/generation_charges и права миграционного пользователя.
6. Если web и worker развёрнуты отдельно, отключить встроенный worker на web: выставить `PROSTUDIO_WORKER_ENABLED=0` и `SUBSCRIPTION_REMINDER_WORKER_ENABLED=0` в переменных окружения web-сервиса. Для отдельного Railway-сервиса воркера использовать `railway.worker.json` (тот же Dockerfile, `startCommand: python worker.py`, без HTTP healthcheck — worker не поднимает FastAPI). Выполнить постепенную остановку старых workers, чтобы не смешивать старую схему списания с новыми резервами. Не включать старый код обратно, пока есть активные новые резервы.
7. Проверить сценарии двумя тестовыми пользователями в Telegram: вход, профиль, история, файлы, генерация/очередь, отмена/ошибка, баланс, скачивание и публикация. Использовать sandbox платежей. Для PayPal подписка связывается через server-signed custom_id и данные PayPal; начисление происходит по завершённому платежу, а не просто ACTIVATED.
8. Проверить по одному реальному запросу каждого включённого AI-провайдера с ограниченным бюджетом, перезапуск worker, возврат резервов и скачивание после перезапуска.

## Совместимость и ограничения

- Подпись Telegram обязательна для приватного API. Браузерный preview больше не может изменять пользовательские аккаунты без Telegram. После истечения `TELEGRAM_AUTH_MAX_AGE_SECONDS` нужно заново открыть Mini App для новых initData.
- `api-auth.js` добавлен перед прикладными скриптами; credentials уходят только на API того же origin. Внешние интеграции с этим API тоже должны передавать `X-Telegram-Init-Data`. Если отдельный серверный бот обращается к API без initData, до rollout ему нужен собственный ограниченный service-auth контракт; постоянный обход авторизации не предусмотрен.
- Ссылки на файлы имеют ограниченный срок действия. При чтении истории структурированные URL обновляются; текст пользователя и содержимое скачиваемых документов не переписываются. Уже переданная ссылка остаётся capability до истечения срока. При необходимости немедленного индивидуального отзыва требуется отдельная политика ревокации.
- Известные исторические покупки, записанные старым кодом без последующего начисления из-за сбоя, автоматически не доначисляются: сначала сверить с реальными платёжными квитанциями. Это защищает от двойного начисления.
- В production не следует оставлять публичный R2. Подписанные ссылки приложения не закрывают ранее опубликованный bucket.
- Бизнес-функции бота, обработка возвратов/споров, аудит администраторов и политика хранения требуют проверки вместе с другими компонентами системы: этот репозиторий не содержит полного развёрнутого окружения.

## Проверки

`python -m pytest tests/test_db_pool.py tests/test_character_prompts.py tests/test_provider_resilience.py tests/test_storage.py tests/test_security_boundaries.py` — изолированные проверки без загрузки `.env` и запуска consumers.

`tests/test_billing_transactions.py` проверяет транзакции в отдельной PostgreSQL-БД через `SYLVEX_TEST_DATABASE_URL`. НИКОГДА не указывать production: тест пересоздаёт свои таблицы. Во время разработки использована PostgreSQL WASM (PGlite): настоящий SQL и транзакции, но не сетевой PostgreSQL и не проверка конкуренции реплик. Нативный сервер PostgreSQL нельзя было запустить из-за запрета shared-memory syscall в среде диагностики.

`python -m pip_audit -r requirements.lock --no-deps --disable-pip` — аудит зафиксированного состава. На дату проверки известных уязвимостей не обнаружено; это не гарантия отсутствия неизвестных дефектов.

Перед откатом проверить `generation_reservations WHERE status='reserved'`. Не удалять эту таблицу и не возвращать старый worker, пока резервы не завершены или корректно освобождены новой логикой. Для аварийного восстановления сначала остановить потребителей очереди, снять backup и сверить reservations/generation_charges/jobs; не выполнять массовый возврат без сверки.

Основания изменений PayPal: [custom_id](https://developer.paypal.com/api/subscriptions/v1/definitions/subscription/), [получение подписки](https://developer.paypal.com/api/subscriptions/v1/subscriptions-get/), [PAYMENT.SALE.COMPLETED](https://developer.paypal.com/api/rest/webhooks/event-names/). Telegram: [валидация initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
