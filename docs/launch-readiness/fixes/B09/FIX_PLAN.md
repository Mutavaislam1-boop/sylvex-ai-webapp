## S7-04 — удаление Telegram-аккаунта через поддержку

**Ветка `claude/b09-telegram-erasure`, коммит `9810451`.**

Новый код только **принимает запрос**. Само удаление выполняет существующий обработчик B09-WEB (`accept_confirmed_request(ecosystem='telegram')`):
- журнал удалений на томе;
- отзыв сессий;
- ожидание очистки кэша бота;
- платёжные записи сохраняются;
- повторное применение удаления при восстановлении из копии.

### Порядок

1. Человек пишет в поддержку (почта или чат).
2. Владелец открывает карточку пользователя → «Удалить Telegram-аккаунт» → указывает обращение и причину.
   - Право Critical `users.delete` (по умолчанию только у владельца) и повторный ввод 2FA.
3. Бот отправляет **в Telegram-чат этого аккаунта** одноразовый код.
   - Код действует 24 часа.
   - В консоли кода нет; в базе хранится только хэш PBKDF2, при закрытии он очищается.
   - Текст сообщения: «сообщите код, только если удаление запросили вы».
4. Человек сообщает код поддержке.
5. Владелец вводит код и **повторно набирает Telegram ID**. Только тогда запрос принимается.

### Защита

- **Ограничения кодов:**
  - 5 неверных кодов закрывают запрос;
  - не больше 3 кодов в сутки;
  - одновременно открыт только один запрос;
  - запрос можно отменить.
- **Код не отправляется, если:**
  - это аккаунт сайта (там своё самоудаление);
  - аккаунт объединён с другим;
  - запрос на удаление уже есть;
  - человек в команде;
  - **подписка Telegram Stars ещё продлевается** (обработчик удаления отменяет только Stripe; поддержка сначала отменяет подписку существующей кнопкой);
  - администратор пытается удалить собственный аккаунт.
- При подтверждении все эти условия проверяются заново.
- **Аудит (critical):** код отправлен / не доставлен / заблокирован / отменён / удаление принято. Код в аудит не попадает.
- Таблица `sylvex_tg_erasure_confirmations` внесена в политику удаления как служебная. Иначе обработчик держал бы все удаления с отметкой «неизвестная таблица».

## S7-04: самостоятельное удаление и повторная регистрация (11.11.2026)

**Решение владельца:** после завершения удаления человек может снова войти с тем же Telegram ID. Он получает новый пустой аккаунт.

| Ветка | Коммит | Что |
|---|---|---|
| API `claude/s704-self-service` → `release/sx010-api-20261108` | 0310831 | кнопка «Удалить аккаунт» в профиле Mini App, `POST /api/account/telegram-delete/start` и `/confirm` (initData Telegram, без админа и 2FA), предложение отключить автопродление Stars, закрытие сеанса |
| API `claude/s704-reregister` → `release/sx010-api-20261108` | 92dfa96 | повторная регистрация (ниже) |
| Бот `claude/s704-reregister` → `claude/sx010-purchase-dates` | 1c69880 | бот пропускает Telegram ID, который освобождён после завершённого удаления |

### Как работает (механизм B09, вторая система не создаётся)

1. **Запрос принят (`queued` / `purging`).** Telegram ID заблокирован везде: проверка доступа API, `blocked_subject`, запись в хранилище, триггер БД `sylvex_erasure_write_guard`, бот (`pending()` / `begin_update()`).
2. **Завершение (`complete`).** В той же транзакции, что и очистка данных:
   - у прежнего SYLVEX ID `active_telegram_id` становится NULL, его сеансы отзываются. Строка остаётся записью запроса;
   - Telegram ID получает новый SYLVEX ID от существующего `sylvex_allocate_telegram_account_id()`, с `origin='telegram'`;
   - `users`: баланс 0, подписка `free`, имена удалены, `created_at` равен моменту завершения.
3. **Блок снимается** только для завершённого запроса, у Telegram ID которого есть новый SYLVEX ID. Это условие `RELEASED_SQL` одинаково в API, в триггере БД и в боте.
4. **Новый аккаунт пустой.**
   - Платёжные записи прежнего аккаунта хранятся по закону, но новому не показываются. Покупки, списания и рефералы скрываются по дате завершения.
   - Подписки скрываются по `expires_at`: в Production `subscriptions.created_at` имеет тип TEXT и не заполняется. Удаление отменяет все `active` подписки.
   - Соглашения Stars скрываются по `created_at`.

### Защита от восстановления из копии

- Строка запроса и запись журнала остаются. Старый запрос не трогает новый аккаунт: он `complete` и повторно не обрабатывается. Воспроизведение журнала (replay) находит его завершённым.
- Копия, снятая **до** удаления: replay снова очищает прежний аккаунт и снова освобождает Telegram ID. Это проверено тестом.
